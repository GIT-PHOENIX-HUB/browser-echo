## THE BUILD ARCHITECTURE

### Builders (2-3 CLIs)
- Multiple CLIs running code, writing code
- Code will be reviewed, tested, confirmed, and committed
- Repos prepped and ready for every step and every set of code we plan to push
- Copilots and agents ready for the code to come — knowing what it is, knowing how and what they're going to do to get it ready for production

### Oversight (4-5 roles)
- Managing, overseeing, verifying, testing, reviewing
- Documenting, logging, maintaining context
- Managing the output so when we're done building we don't have a week's worth of mess — instead we have functional, actionable code
- Every CLI, every agent that is working will have somebody over top of it keeping tabs

### Context Keeper
- A dedicated role that maintains context across all sessions
- Watches context usage on every CLI

### Guardian Agent
- Has ability to control Shane's Mac
- Can step in at any moment and wake up a CLI
- Can restart a CLI
- Can troubleshoot an error

### Logger
- A CLI or Llama strictly in charge of logging and documenting every CLI action
- OR: every CLI will have subagents, and one of their agents will be specifically positioned to log and document every step

## THE RULES

### Context Management
- Each CLI stops at 3/4 of its context — does NOT keep working past that point
- In fact it will not have any more work to do at that point
- Each CLI is issued the context it needs AND the prompt it needs to successfully complete its objective

### Code Quality
- Every piece of code: reviewed, tested, confirmed, committed
- Repos prepped and staged for every step
- Copilots and agents briefed in advance — they know what's coming
- Output is clean — functional, actionable code, not a mess

- Everything staged before the build starts
