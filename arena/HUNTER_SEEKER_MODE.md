# Hunter Seeker Mode

> Future continuous-monitoring mode for Browser's full arena.

## Intent

Hunter Seeker Mode is the future state where Browser wakes proactively,
searches approved surfaces for signal, and returns with actionable briefings for
the team.

This is not random wandering. It is disciplined monitoring.

## Core Behavior

Hunter Seeker Mode should eventually allow Browser to:

- wake on a schedule or approved trigger
- scan approved sites and systems
- find upgrades, changes, risks, and opportunities
- summarize what matters
- produce calls to action for Echo and Codex
- log those calls to action into the builder-ledger workflow for CLI pickup

## Initial Target Cadence

When this mode is implemented, the target rhythm is:

- morning briefing
- midday briefing
- evening briefing

The exact cadence can expand later, but the early goal is three strong reports a
day rather than constant noise.

Those reports should become the team's standing rhythm for:

- email and inbox triage
- GitHub review and repo cleanliness
- website and admin-surface monitoring
- upgrade and opportunity scanning

## Approved Signal Sources

Potential hunter-seeker sources include:

- GitHub org activity and repo cleanliness signals
- Microsoft email and inbox signals
- release notes and vendor updates
- Microsoft and Azure change surfaces
- websites and admin surfaces Shane has approved
- service software changes and opportunities
- leading-edge technical developments worth evaluating for Phoenix

## Output Format

Each hunter-seeker run should produce:

- what changed
- why it matters
- urgency level
- recommended next action
- which agent should own the action
- where the action was logged

## Guardrails

Hunter Seeker Mode should not become a license for uncontrolled mutation.

Default behavior is:
- observe
- summarize
- recommend
- log

Mutation still follows the approval model.

## Repo Stewardship Lane

Hunter Seeker Mode also includes continuous repo stewardship:

- cleanliness
- stale artifact detection
- continuity drift detection
- documentation decay detection
- opportunities to improve structure and leading-edge capability

Browser should always be looking for how the system can stay ahead without
becoming chaotic.

## Status

This mode is approved as a strategic direction, not yet fully automated.

The extension, the repo, and the team workflow should evolve toward it in a
disciplined way.
