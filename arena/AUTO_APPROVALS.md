# Auto Approvals

> Quick-reference registry for actions Shane has pre-approved by category.

This file exists so Browser can move quickly without making Shane repeat the
same approval every session.

## How To Use This File

- If an action type is listed here as approved, Browser may proceed inside the
  stated scope.
- If an action is not listed here, Browser should ask.
- If an action touches archive movement, the archive manifest rule still applies.

## Approved Categories

### 1. Filing And Organization Inside Known Project Surfaces

Approved when:
- the project boundary is clear
- the destination structure is already known or already documented
- no delete is involved

Examples:
- placing files into their correct folders
- normalizing known filing layouts
- cleaning obvious clutter inside a known repo or workspace structure

### 2. Repo Cleanliness And Continuity Improvements

Approved when:
- the repo is already a known Phoenix surface
- history is preserved
- archive-first rules are honored

Examples:
- improving bootstrap docs
- improving handoff files
- tightening README accuracy
- improving issue architecture and continuity docs

### 3. Daily Review And Monitoring On Approved Surfaces

Approved when:
- the surface is already known and approved
- the action is observation, summarization, or reporting
- no external mutation occurs

Examples:
- GitHub review sweeps
- website status checks
- release note scans
- operational briefings

## Not Auto-Approved

The following still require explicit approval unless Shane later adds them here:

- archive moves without manifest review
- new external systems
- account-level setting changes
- billing or payment changes
- credential rotation
- permission changes
- content publication on live external business surfaces

## Maintenance Rule

This file should stay short and legible.

If Browser repeatedly needs to ask for the same category, Shane can add that
category here and the system gets faster without getting sloppier.
